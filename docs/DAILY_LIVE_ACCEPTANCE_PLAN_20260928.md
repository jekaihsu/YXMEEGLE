## 一筆新日報成功配對的必要條件

1. 選擇已匯入的 V4「工程確認單」，其「工程確認單編號」非空且對應唯一正式案件；不能選沒有編號的 182 列之一，亦不能只輸入同名工程或同名同事。
2. 新日報的「所屬案件」要真的選取該確認單，API 必須返回相同 Base／確認單表的 record_ids。
3. 需要合約工項時，外業選「合約工項」、內業選「內業工項」，目標皆為「合約填報工項」。該工項的「來源合約明細（日報關聯）」須能沿合約明細的「所屬成案確認單（日報關聯）」唯一回到同一案件。若案件已選對但工項上游未接通，系統仍保留待核對，不能忽略壞掉的工項關聯。
4. 「所屬成本單」指向對應內／外業成本单，具真實工作日期與組別。日報公式日期與成本單日期須一致；未知日期不得用匯入日代替。
5. 同事識別須為同一應用的原生人員 ID。名字僅供顯示，不作認證或案件匹配。

## 可直接執行的驗收步驟

本次未新增遠端業務紀錄。請在下一笔真實工作日報或公司另行核定的隔離測試資料上執行；不要為驗收填造薪資、營業額或正式工作成果。

1. 記錄同步前正式案件數、該案日報數、日報來源 ID 集合與來源同步時間。選擇上述關聯完整的一個既有案件。
2. 從既有 Lark 日報正常填報入口，新增一筆真實內業日報，選成本單、案件及適用工項，保留新增來源連結／record ID；外業日報以相同步驟再驗一筆。表單產生關聯後，先以唯讀 API 確認 record_ids 與工項上游鏈。
3. 在正式工作區執行 `/api/sources/sync`，或等候既有五分鐘同步。記錄本次 `last_sync`／`sync_revision`，不得只看 HTTP 200。
4. 在該案「日報紀錄」找到相同 Base＋table＋record ID 的唯一一筆：案件、日期、組別、人員 ID、內容與來源連結相符；案件數不增加，SOP 子任務狀態不被自動完成。
5. 原筆再同步兩次，仍只有一筆；由原填報流程更正同筆內容後再同步，應更新同一 ID，不能再開案或重複日報。需更正關聯時走真實核定流程，不任意改正式資料測試。
6. 日報／成本單上的檢核欄位只顯示原始狀態；匯入不等於工作台節點核准，也不回寫薪資 Base。

失敗案例（空關聯、未知關聯、多案件、案件與工項衝突、部分鏈缺失、日期矛盾）已在本機合成資料覆蓋，正式環境不必為測試故意寫入錯誤資料。舊 535 筆保留待核對，不影響以新增 record ID 單獨判定新流程通過。
