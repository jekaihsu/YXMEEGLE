## 3. 欄位語意與轉換

| 應用欄位／概念 | 來源規則 | 檢查與限制 |
| --- | --- | --- |
| project.code | 優先使用已確認工程案號；同時保留報價編號與來源 record ID | 工程確認單編號可能隨接案階段變化，不能當永久主鍵 |
| project.name／client | 報價及確認單中的名稱／業主來源欄位 | 以已驗證欄位設定讀取；未知不從文字猜測 |
| work_item_id | 來源表及 record ID 對應內部穩定工項 ID | 文字工編或來源明細唯一鍵可能重複，不據此刪重 |
| estimated_points | 各部門對應營業額／預估工作量 | 單位為組日；與 contract_amount 分開，不按多人重算 |
| task.points | 對工項工作量的 SOP 分配 | 不增加來源總額；顯示未分配與超配 |
| V4 基準數量 | 依類別取合約明細的外業／控制／圖資／報告數量 | 是該工項合約作業量，不等同每日產量 |
| V4 標準點數 | 來源「對應營業額」，歷史描述空白為 0 | 應保留來源缺漏狀態，不以 0 證明真實沒有工作量 |
| DailyReport.date | 日報／所屬成本單工作日期 | 使用台北業務日期，不以紀錄建立或同步日期替代 |
| DailyReport.case_code | 正規化為已匹配專案的工程案號，原值另存 source_case_code | 同時使用報價編號、確認單及工項連結；多義不自動配案 |
| DailyReport.department／person | 來源組別、人員 ID 及可讀名稱 | 身分授權不以姓名作唯一鍵 |
| DailyReport.points | 優先讀取來源「最終營業額點數」，缺值才使用「營業額點數」 | 是來源公布值，非 Web 計算或 Web 核可值；不自動分给各 SOP |
| source_url | Base＋table＋record ID | 使用者可追溯原始紀錄，前端不含來源憑證 |
| due_date | 首次可帶入有效來源期限；缺值由節點主管排程 | 已建立後提前及延後都須核准審批執行，不由每次同步覆蓋 |
| started_at／completed_at | 應用流程操作 | 日報紀錄不直接覆蓋，流程時間與工時分離 |

原始點數、修改後營業額、核可點數若要顯示，需分別讀取來源欄位與檢核狀態；若最小 API 僅提供 DailyReport.points，不宣稱已支援另外兩種值。擴充時先更新 API 契約再加前端欄位。

## 5. 同步完整性、登入與審批邊界

八表以登入者的 user_access_token 唯讀存取；不由匿名示範工作區使用 bot 身分讀取。欄位先分頁取得，再只讀取設定的必要欄位。records 每頁 200 筆，LARK_SOURCE_MAX_PAGES 預設 50（每表最多 10,000 筆，可調至 100 頁）；達上限仍有下一頁時，整體及該表皆標 partial，附讀取頁數及上限。partial 不能視為全表驗收，更不能據此斷言案件當日未作業。欄位 schema 20 頁未讀完、缺漏／重複游標或重複 record 皆明確失敗並保留上次成功快取，不把不完整資料呈現為成功。

OAuth 明確請求 LARK_OAUTH_SCOPES，預設僅 bitable:app:readonly；需讀既有審批時再加入 approval:approval:readonly，且必須在 App 的 user 權限、發版及使用者授權中生效。callback 驗證一次性 state、tenant allowlist 與 Lark 回傳身分。LARK_ROLE_MAP_JSON 由伺服器將 open_id 映射至 pm／manager／member，未列出的使用者一律 member，首位登入不自動升權。PM／manager 才能啟動來源同步。

既有審批讀取使用支援 user token 的 GET /open-apis/approval/v4/instances/detail，以 instance_code 查詢；GET /open-apis/approval/v4/instances/:instance_id 為 tenant token 端點，不混用。依據為官方 SDK detail_instance_request.py 與 get_instance_request.py，對照連結見 backend/INTEGRATION.md。讀到 APPROVED 只更新外部狀態，不代表已驗證本案、本版本與三線確認。未完成正式 submit adapter 時，live 送審回 503、保留草稿、不凍結任務；僅配置 approval code 不會啟用假送審。模擬核准只供隔離 demo。
