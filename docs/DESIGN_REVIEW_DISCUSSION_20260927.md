## 不能直接照做的建議

1. **第 5-f 節凍結完成動畫、關閉 @ 收件入口，與使用者點名需求衝突。** 使用者要真正大節點完成才回饋，並要標註同事與收件入口。目前方向保留：伺服器確認完成才觸發；待審、跳過與重新整理不冒充完成；減少動態設定有效。@ 已明示只在工具內標註，不發 Lark 訊息。它沒有對外推播是既定界線，不能因此自行刪除或改成轉發。Lark 每日提醒是另一項需求，須分別驗收。
2. **第 5-c 節「代理用改派」會改變業務語意。** 代理有期限、範圍、被代理人與實際操作者，並受同人不得佔兩席限制；永久改派不能替代。可以簡化顯示，但後端和操作說明須保留這些差異。
3. **第 5-c 節將 Input／Output／成果批次一律叫附件，不足以承載已核定流程。** 結構化欄位不是檔案；成果批次含數量、金額、版本和請款關係。可用易懂詞及漸進揭露，不能把財務證據與版本關係抹掉。一般使用者也須能辨識正式／測試環境，不能只讓管理員看環境標示。
4. **第 3-b 節只讀一份確認單是待證明的來源簡化方案。** 相同列數不足以證明兩表內容、更新時機和欄位權威相同。既有決策是 V4＋報價總表；可以對重複資料建立明確來源與優先規則，但不能直接砍一個來源或丟失多報價、接案與正式案的關聯。
5. **第 3-c 節 Input 改專用登錄表、全面關閉正式寫回，不能自動擴張成新決策。** 已核定為驗證映射後寫 Base、檔案寫 Drive，原始來源不可任意改。未驗證或不安全的 table／field 映射應擋住；是否另建登錄表需提出欄位與責任方案。最新能力／薪資 Base 的全面寫入禁令必須執行，但不能類推為所有 Base／Drive 功能全部停用。
6. **第 0-a、5-a、5-e 節重整節點與五畫面，是設計方案而非既定需求。** 去掉重複任務、縮短補件路徑值得做；「節點只剩顯示」「開始併入完成」「取消交付表」必須仍保有 PDF 分工、真實開始／完成、適用產出與分批交付規則。先修違反不變量的行為，再評估是否需要資料模型遷移，不能以畫面簡化代替業務證據。

## 不需要再次請業主決定的技術工作

以下項目有可靠重現時可在既有授權內修復。實作方式需要工程評估，無須詢問使用者是否接受越權、錯配或資料遺失。

| 類別 | 既有要求／驗收不變量 | 修復時需保留的限制 |
| --- | --- | --- |
| 權限與隱私 | 新操作用當前權限；停用者不得新指派；敏感請假／人事與封存內容不向無權者回傳；同人不佔必要兩席。 | 歷史簽署當時有效性與現在是否可新操作要分開；不能停用一人就悄悄撤销其過去有效簽核。 |
| 案件與日報一致性 | 精確身分、不猜測合併；未知或歧義關聯不能假裝唯一命中；上游歸屬改變須重新核對。 | 只讓與歸屬有關的變動失效人工配對；一般檢核或無關備註變動不應洗掉已確認歸屬。 |
| 刪除與同步 | 只有完整成功的來源快照能作缺席／刪除判定；失敗保留最後成功資料。 | 保存歷史與刪除來源的稽核線索，不能用部分讀取把案件或成果刪掉。 |
| 狀態與期限 | 送審不等於完成；依法核准的展延不可被一般重算覆蓋；重複事件不能無故增任務或撤回成果。 | 真正工作範圍變更仍須使相關核准重新核對，不能為避免干擾而關閉所有失效檢查。 |
| 財務與版本 | 批次成果、數量、金額、同意綁定同版；非相關更新不重開全部財務；V4 業務狀態不能繞過結清條件。 | 試行是否開放財務由 Q2 決定；一旦開放就必須滿足既有雙方與結清規則。 |
| 遠端未知結果 | 顯示待核實並提供安全恢復；沿用同一識別讀回核實，不盲目重建。 | 本地成功、假 HTTP、回傳 APPROVED 字串都不是完整遠端證据；恢復操作須重新驗權限與綁定。 |
| 並行與可測試性 | 未知 action 拒絕；背景資料更新不應任意覆蓋使用者業務變更；規則須有回歸測試。 | action registry、獨立 jobs 表、outbox 是可選工程方案；不能僅憑預估天數把全面重寫當唯一可行修法。PostgreSQL 並行性須在相符環境驗證。 |

- **「協作四件全缺」過度概括。** 本輪已有檔案 ownership 交接、獨立審查及決策回歸證據；是否具備自動合併閘門、格式檢查、分支與提交紀律要另查。需要改善的工程流程不等於既有驗收全無效，也不適合在多 agent 同時寫檔時直接全庫格式化。
- **學習路徑相關描述已被 D1–D3 取代。** 訓練、能力認定、考評整塊停用；一般管理設定不能開啟，歷史保留。班表、報價認定與動態名冊唯讀同步保留。不能從原文「學習路徑沒有後處理」推導應重新啟用學習，或連管理功能一起停用。
- **原生審批模組通過不是正式串接已驗收。** 定義、實際人員席次、發起、本人核准、查回、撤回與業務套用須有各自證據。工作台入口的產品決策可以明確，正式串接仍應如實顯示待設定／待核實。
- **已修問題保留歷史但標版本。** 權限投影、代理 `can_execute`、Mention 送出焦點與學習封鎖已有後續修復紀錄。原問題可作回歸依據，不應永久列為未修；反過來也不能因某次測試通過就宣稱所有新發現的權限、範圍版本或並行問題都已排除。
- **「已重現」與「讀碼推論」分級處理。** 原文估時不是驗收證據；讀碼疑慮需要最小重現、影響範圍與修復後反例測試。對重大風險先限制未驗證操作，但不將尚未證實的假設轉成使用者要接受的業務規則。
