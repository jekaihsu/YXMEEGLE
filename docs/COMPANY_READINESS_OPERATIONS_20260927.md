# 公司使用準備度：部署與維運獨立核對

2026-09-27，root 對照使用者要求及實際程式、私有備份驗證紀錄。此文件不把本機測試、設定檔或應用 scope 當成正式端到端成功。

## 判定方法

- P0：在宣告完整公司正式使用前必須排除；相關功能不可假設已可用。
- P1：受控試用前需修正，或先限制受影響功能並明確記錄負責人與驗收條件。
- P2：不影響當前正確性的改善。
- 以通過具體驗收條件判斷，不以任意完成百分比估算。

## 已具備的基礎

- 真實舊版 PostgreSQL、附件備份已取回，隔離還原逐項比對通過；升級與真實來源重匯入演練有紀錄。見 `CLOUD_BACKUP_EVIDENCE_20260927.md`、`CLOUD_SOURCE_REIMPORT_20260927.md`。
- `scripts/run_service.py` 會先確認 web 的資料庫健康，再啟動 worker；任一程序非預期退出則停止另一程序並退出，讓平台重啟。`backend/test_runtime.py` 有實際子程序測試。
- 來源同步失敗不取代上一份完整快照；資料連線成功和待配對資料分開顯示。
- production 要求 PostgreSQL、固定強 session 密鑰；部署 allowlist 排除憑證、私有快取與測試資料。
- 本輪新增節點跳過後，完整後端 246 項測試通過。後續權限及 UI 修改須另行重驗，不能沿用為最終結果。

## 目前可作的結論

可繼續本機/隔離資料驗收及指定範圍試用準備；尚無足夠證據宣告整套可取代公司正式流程。正式啟用須按功能開放，維持未驗收功能的草稿或待設定狀態。公司規則未核定的部分另列決策，不由 agent 自行填補。
