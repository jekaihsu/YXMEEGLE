# 安全與新舊案基準實作紀錄（2026-09-30）

本紀錄描述本機程式與合成測試，不代表已部署或已在公司資料建立切換基準。沒有代同事核准、寄送訊息、修改薪資 Base，沒有變更遠端資料。

## 輸入、通知與權限

- `input_validation` 在 HTTP 與 domain action 前驗證文字／ID／清單／布林型別，文字最多 10,000 字、標題與名稱 240 字、完整 action 256 KB；禁止用 payload 寫 OAuth 或公司授權。Meegle 來源契約的正整數 template_id 明確允許。
- 參考連結僅接受公開 HTTPS 標準埠；拒絕帳號密碼、控制字元、內網 literal IP 與 localhost。此功能不從伺服器抓取連結，不將使用者連結標成官方來源。
- Lark @通知只送固定文字與伺服器工作台連結；留言、案件名稱與同事名字不插入機器人訊息，避免可編輯文字帶入偽造公司連結。
- 通知在同一 workspace 交易內預留額度：每 actor 每分鐘 20 位收件人、每 recipient 每分鐘 10 則、每 workspace 每分鐘 100 則；超限 429 不建立留言／工作。同一 request receipt 不重複計費或排送。
- manager 不再自動等於每案 PM／任務負責人。最新核定的 jekai 普通業務備用權需伺服器 grant 明列 `scopes: ["company:ordinary_business_backup"]`；每次身分與工作區載入重建權限。缺 scope 只保留登入及管理功能。
- 備用權可處理普通工作，不改案件或任務固定負責人；核准席位仍精確驗證，不能代替財務／原生共同審批兩席。public self 只回傳 `can_business_override` 布林，不回 grant 或 OAuth 證據。
- 人員 API 改成欄位白名單；只有本人可見自己的 capabilities。日報與來源 API 不回傳薪資／津貼原始公式、人員識別附加資料，保留核定可讀的案件財務與正規化日報。既有非文字 title 等僅在回應中顯示格式待核對提示，原始資料未覆寫。

## 來源基準與舊案隔離

- 管理員必須核定完整、與成功同步 revision／時間一致的來源快照。基準保存全部 Base／table／record 身分、既有案件碼、快照 hash、來源表集合、核定人與時間；不能任意重建基準把新案重新歸為舊案。
- 同步請求 `automatic_fields=true`，保留 Lark 原生 `created_time`。參數依 [Lark 官方 Python SDK](https://raw.githubusercontent.com/larksuite/oapi-sdk-python/v2_main/lark_oapi/api/bitable/v1/model/list_app_table_record_request.py) 核對。
- 只有原生建立時間晚於切換時間、身分與碼不屬基準、原生關聯未連到舊案的新案件才自動進入工作台。首次發現不等於新建；沒有建立時間／關聯不完整只產生最小管理待確認條目，不建立整案。
- 舊案新增加報價仍被排除；舊確認單即使已從最新快照刪除，基準身分仍阻止它的新增報價變成新案。證實建立於切換前的延遲發現紀錄不進待辦。
- 已匯入案件以 `excluded_history` 軟隔離保留歷史，不能從既有「案件歸屬」功能翻回工作台。正式 UI／API 投影排除舊案、其任務、審批、事件、背景工作、日報、來源實體及附件；多案來源與無歸屬孤兒亦採保守排除。來源表公開數量重新以可見紀錄計算。
- 基準與原始資料留在伺服器。`source_case_review` 僅管理員可見；正式員工不取得原始基準身分清單。

## 驗證

162 項相關測試通過：安全邊界、標註、來源與人員投影、新舊案基準、來源同步、管理員與員工 OAuth、審批功能旗標、案件切換及准入。另測試 backend OAuth、gzip 與 native approval refresh 3 項通過。

新增回歸包含：物件型標題拒收、聚合 request 大小、URL 變體、所有可編輯通知欄位夾惡意連結、交易限流、明確備用權撤銷後立刻失效、備用者不能代核准席位、來源私有值不外洩、切換前後建立時間、舊案新增報價、已刪除舊確認單關聯、延遲發現舊案、來源表集合變更、所有舊來源集合哨兵字串不出公開資料。

待整合驗收：完整後端測試、正式服務發布、完整快照與遠端基準核定、環境中的明確備用 scope、真實員工審批、24 小時觀測。不得以本機測試通過宣称這些已完成。

## 最後 HTTP 隔離驗收

新增 40 項 HTTP 專項全通過；另 42 項既有 Input 與公司准入回歸全通過。

- `/api/audit` 的普通活動日誌排除舊案紀錄，管理員也不例外；混合新舊案的單筆稽核不直接公示。歷史完整紀錄仍留在 DB。
- `/api/admin/audit/history` 僅管理員可讀，回傳操作者、動作、時間、結果、案件 ID 與變更數量等 metadata，不回傳歷史來源、留言或人員欄位內容。
- Input 登錄、查回與映射驗證端點先驗 JSON 物件、正整數工作區版本及 64 KB 請求上限；list/null/錯誤型別/壞 JSON/NaN 回 422，不改 DB。Input 的 value 仍可為有效 JSON，並沿用原本 50 KB 內容限制。
- Input 登錄在交易內重取目前操作者權限；查回與映射驗證不接受已隱藏舊案的項目。
