# 流程補件與審批入口 — 新增需求

使用者在檢視新版介面後提出三項需求：

1. 點大節點的「完成節點」時，若小任務未完成，直接開啟可處理的小任務內容，逐項補齊並完成。
2. 希望某些節點可以申請跳過，經審批後處理。
3. 全面檢查類似「操作被擋住，卻沒有直接補件入口」的情境。

## 已確定的實作方向

- 大節點完成入口改成引導處理：列出未完成任務，直接進入任務內容，處理後接續下一筆，再回到大節點核對。
- 沿用真實任務權限、必要附件／成果、審核與版本檢查；不將引導入口當作批次假完成。
- 缺附件、未指派、退回補正、審批未完成及日報待配對，檢查是否能直接導航至對應操作。
- 跳過節點應保留申請原因、影響、核准紀錄，呈現「核准跳過」而非偽裝成已完成。
- 財務與結案先維持先前核定的雙方確認及結清條件；變更此規則須另外明確核定。

## 已核定的跳過審批政策

2026-09-27 使用者明確回答：**PM＋該組主管共同核准**。

- 一般工作節點可提出申請，兩個角色須由不同實際人員核准。
- 申請須記錄案件、節點、受影響任務、原因、後續影響及當時的版本與責任人。
- 核准後顯示「核准跳過」及原始申請紀錄，不將未做的任務、成果或附件偽裝為完成。
- 財務與結案仍依原先雙方確認與結清條件，不納入一般節點跳過。
- 正式 Lark 送審尚未完成設定及驗收時，只能保存申請草稿，不得用示範核准變更正式案件。

## Lark 審批真實界線

已核實請假審批的代理人欄位；設計變更、展延及新增節點跳過，尚未完成正式送往 Lark、核准回傳及工作台執行的端到端驗收。示範審批不等於真實送審成功。由獨立 agent 調查既有審批定義及實作缺口，不以假映射填補。

原視覺改版已完成初版與主要審查；本次新增需求仍在整合，因此尚未將本輪新程式部署至正式站。
