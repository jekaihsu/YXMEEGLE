## 代理來源的新鮮度與失敗處理

- 只有伺服器查證的 `APPROVED` 且 `verified_at` 距今 0–300 秒可授權；過期、未核實、無時區、未來時間、撤回、刪除、拒絕或未知狀態均拒絕。
- 建立代理時核對人員與請假範圍；實際操作另核對完整請假起訖時間，不把半天請假放大成全天。
- 已配置公司的應用身分時，worker 每四分鐘以唯讀 GET 更新已被有效代理引用的實例；不列舉其他人的請假資料。失敗立即把快取標為 `UNKNOWN`，保留最後核實时间作稽核，下一次重試至少間隔一分鐘。
- 未配置背景身分時，只能沿既有已授權的手動來源查證更新。過五分鐘停止代理權，不以舊快取繼續授權。
- 用戶手動來源查詢使用使用者端點 `/approval/v4/instances/detail`；背景應用使用租戶端點 `/approval/v4/instances/{instance_id}`。兩者身分契約不同。租戶 GET 路徑、token 類型及回應欄位由 [官方 SDK request](https://raw.githubusercontent.com/larksuite/oapi-sdk-python/v2_main/lark_oapi/api/approval/v4/model/get_instance_request.py)、[官方 SDK response](https://raw.githubusercontent.com/larksuite/oapi-sdk-python/v2_main/lark_oapi/api/approval/v4/model/get_instance_response_body.py) 核實；這證明 API 契約，未證明本公司的應用已取得該權限。

## 寫回與復原規則

- 訓練紀錄以 `workspace:plan_id:version` 為不可變版本鍵。已有版本永不 PUT；內容不同為 `conflict`。新版本新增一筆，保留舊版與外部修改。
- 技能關聯須指向同一能力 Base 內唯一的「能力地圖總表」，不是任意 link 欄位。查不到或同名即停止。
- 不明 POST 結果先依版本鍵查回；無法核實則保留 `outcome_unknown`，不盲目重送。建立後仍查重並逐欄讀回。
- 工作租約過期時，queue 與訓練／能力／Input／文件／確認單狀態一起改為結果待核實。舊版本工作的失敗不能覆蓋新版訓練的完成狀態。
- 正式班表來源、訓練資料目的、Base 欄位映射、Drive 根目錄及應用授權未核實前，維持待設定／待核實；不造出成功資料。
