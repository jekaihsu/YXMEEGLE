## 尚須核實的外部設定

1. 專用軟體應用的 Base 讀取及必要寫入權限；正式同步與寫回須分別驗收。
2. 原生設計變更／展延的審批定義與欄位映射、案件和任務範圍。請假代理審批不能替代它們。目前正式送審明示未開通。
3. Attendance 的正常班表來源及讀取身分；已知的打卡表只有實際打卡，未取得可用正常下班欄位。
4. 訓練紀錄目的表、欄位及 Drive 目錄；正式能力認定者須明確指定。`LARK_CAPABILITY_APPROVER_IDS` 可為指定 open_id 做一次性初始授權，保留套用時間；之後人工撤權不會在每次請求時被補回。泛用 manager 角色不會自動補權。
5. 真實測試用的隔離 Base／Drive；目前實際驗收仍使用模擬。隔離通道已實作，但未配置真實隔離資源，未取得真實寫入回執。

隔離實測須同時有：`LARK_WORKER_IDENTITY=application`、`LARK_WORKER_ORGANIZATION`、Input 的 `LARK_TEST_BASE_TOKEN` 或文件的 `LARK_TEST_DRIVE_ROOT`；對應的工作區目的必須一致，且明確開啟外部連線。不得把三個正式 Base 或正式 Drive 根目錄當作隔離目的。
