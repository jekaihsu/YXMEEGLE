## 4. 需求

4.1 檢查錯誤率（外業／內業／控制組）：KPI（失誤率、未檢核率、檢核覆蓋率）、12 週趨勢、依組別與人員排行、依工項分布、⚠旗標分布；明細表可篩選排序分頁；圖表點擊套用篩選。
4.2 業務數據：案件狀態分布、預期合約金額、計價與入帳進度、可請款未請、應收未收；案件明細表。
4.3 儀器車輛管理：車輛使用次數與里程、儀器依類別與狀態、閒置天數、送修清單、日租金；多重篩選；缺口提示。
4.4 外業／內業報告：預排達成率（依工程編號）、進行中案件營業額剩餘、本週對預排差異。
4.5 資料來源頁：每個來源表的 Base、table id、使用欄位、列數、最後讀取時間、讀取狀態與缺口。

## 5. 權限

唯讀。沿用 `company_dashboard` 的角色門檻。只顯示彙總與工作單層級欄位，不輸出薪資或成本金額欄，除非角色已具備財務檢視。

## 6. 效能設計與驗收

- 讀取時只帶白名單欄位（Lark list API `field_names`），`page_size=500`，table 級 RPS 限流，跨表有限併行。
- 單飛刷新，TTL 預設 300 秒，過期先回舊資料並背景刷新（stale-while-revalidate）。內容指紋未變則不重算。
- 快取兩層：正規化列（記憶體，可選落地 JSON）與每個快照版本的聚合結果。聚合只在快照變更時重算。
- 明細端點伺服器端排序、分頁，預設每頁 50，最大 200。
- 前端：路由層 lazy、圖表為內建 SVG、表格不一次渲染超過一頁、請求帶 abort 與請求序號。
- 驗收：量測冷啟動（含 Lark 讀取）、暖快取 p50／p95、payload 大小。目標暖快取聚合端點 p95 < 100 ms（本機，真實資料量），明細頁 p95 < 80 ms。附量測腳本與結果。

### 預排達成率修訂定義
