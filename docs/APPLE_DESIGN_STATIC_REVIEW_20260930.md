# Apple Design 靜態複查 — 2026-09-30

範圍：原生審批恢復操作、財務提交入口、SOP 明確改版。已讀使用者指定的 [apple-design SKILL.md](https://github.com/emilkowalski/skills/blob/main/skills/apple-design/SKILL.md)。本次為程式與樣式靜態檢查，沒有新增瀏覽器、手機、螢幕閱讀器或真實 Lark 驗收證據；也不是 Apple 認證。

## 審查結果與修正

- **操作可預期**：明確拒建才顯示「重試原申請」或「結束未建立的申請」；未知結果保留原識別查回。撤回明確拒絕與結果未知分開呈現。
- **即時回饋**：送出時立即停用重複提交，顯示處理中及 `aria-busy`；完成訊息用 `role=status`。503 也重新查詢保存狀態，避免後端已留回執但畫面不更新。
- **入口與實際責任相符**：系統 manager 不再自動看見可建立財務申請的入口。PM、行政、明確備用授權及該財務節點負責人依後端規則顯示；送審另限原申請人或 PM／明確備用授權。
- **層級與恢復路徑**：一個區塊集中顯示原申請狀態、可執行動作、操作結果。結束未建立申請會說明工作不會自動恢復，保留明確恢復程序。
- **靜態樣式核對**：既有 company-workspace.css 可換行動作按鈕與手機文字；workbench.css／styles.css 提供焦點及減少動態、透明度、增加對比設定。本輪不加入額外動畫。

## 尚需瀏覽器實測

由主 Agent 驗證：窄螢幕／200% 字級換行、Tab 焦點、原生確認視窗返回、503 後新狀態、拒建重試沿用識別、撤回未知不重送。CSS 存在不等於尺寸、對比及輔助科技實測通過。

## SOP 改版修正與部署限制

`merge_project_tasks` 的正式呼叫點僅為明確 `sop_apply`。現在既有未完成任務同時更新契約版本、範本版本、責任說明與週期追蹤 metadata，保存變更前後及操作者；不改負責人、既有成果、完成任務或已完成節點。

修正前，舊 `quote_provide` 任務套用新版後仍可能保留舊契約版本，略過下包判定。本次測試驗證：純讀取不遷移；明確套用後，未判定下包需求不可提出報價。未完成節點的舊日報必填要求也只在明確套用後替換；已完成歷史不追改。
