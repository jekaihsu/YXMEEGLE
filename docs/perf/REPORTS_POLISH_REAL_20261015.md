## 瀏覽器請求與版面

此為單次開發環境 sanity check，不是延遲或吞吐量基準。計數使用 Resource Timing 中 `/api/reports/` 請求，確認頁面呈現成功資料，沒有把錯誤回應當成快取成功。資料快照已暖，頁面每次完整導航有新的前端快取。

| 頁籤 | 首次載入 | 60 秒內切回 | 換前一週 |
|---|---:|---:|---:|
| 檢查 | 2，摘要與明細 | 0 | 2 |
| 業務 | 1 | 0 | 不適用，無週條件 |
| 資產 | 1 | 0 | 無週條件，日期範圍變更 1 |
| 進度 | 1 | 0 | 1 |
| 來源 | 1 | 0 | 不適用，無週條件 |

成功結果依端點、排序後查詢條件、工作階段快取 60 秒。保留 AbortController、請求序號與登入工作階段檢查。測試驗證舊請求取消、晚到回應不覆寫、切回快取與登出後回應不採用。

初次實測發現檢查頁載入時明細篩選區移位。現在等待摘要後才呈現該區，業務亦相同。最終 1440 與 390 CSS px 下五頁，各量測一次，PerformanceObserver 的無近期互動 layout-shift 合計均為 0。十種頁面與寬度組合皆無頁面水平溢出、null 或 NaN 字樣。此結果只適用本次快速本機回應，不代表所有網路條件。

五頁均檢查深淺色，等候主題轉場完成後保存 20 張截圖，並重新開啟檢視。桌面 viewport 為 1440×1000 CSS px，T3 snapshot 輸出縮為 1280×889 PNG。手機 viewport 為 390×844 CSS px，PNG 為 780×1688。檔名記錄 CSS viewport。手機圖表與來源表保留各自水平捲動，頁面本身不溢出。
